## Layout and content

- Navigation styling belongs to `NavTabs` so its surface, tab dimensions and mobile layout stay consistent across routes.
- Keep navigation and date controls together in the top toolbar; stack them on narrow screens. The calendar opens as an overlaid popover, with a visible close button, Escape/outside dismissal and focus return on explicit close or date selection.
- Keep the dashboard compact and player-card-first. Use the shared rail/page-gutter variables; let wide screens show useful content.
- Use Finnish labels and numeric dates. Preserve visible game/date context when showing yesterday's feature on today's pre-game view.
- Player cards switch between the summary and extra stats with a short fade and an animated height change. Reduced-motion preferences make the switch immediate. The inactive view is inert and hidden from assistive technology; keyboard focus stays on the active view without scrolling the page.
- Player-card matchups sit at the bottom with team logos flanking the score. Completed wins/losses add a subtle circular green/red glow centered at the bottom edge, with a text result label.
- Goalie save percentages use a semicircle gauge with the label above the exact percentage and the saves/shots breakdown beneath it. The arc is blue from 92% to below 100%, amber from 90% to below 92%, and red below 90%. Exactly 100% gets a metallic gold gradient and glow for a legendary finish. It fills from 0–100%; unavailable percentages keep the empty state. Each card owns its SVG gradient ID so multiple goalies render independently.
- Team logos identify teams. Keep ordinary text and actions neutral/blue; reserve result colors for semantic states with text or accessible descriptions.
- Bundle custom banner artwork through asset imports so image URLs respect the deployment base path. SVG banner text embeds the bundled Onest font and its license so standalone images match the site's typography across devices. Keep the affiliate tracking URL on the enclosing link. All public ad placements use the shared [AdLabel](../src/lib/components/ui/AdLabel.svelte): a consistent, readable `Mainos` pill with a small megaphone icon. Place it in its own row above the artwork, outside rotating links, so it stays still and never covers the creative.
- Desktop side ads stay centered inside white 160×600 slots. Keep each image at its natural size, scaling down when needed to fit; narrower creatives leave white margins at the sides.
- The homepage shows a rotating 300×250 ad between each visible player-position group on mobile, with independent placement state for each slot. Mobile selections use loaded creative IDs, choose randomly every 20 seconds, and avoid the previous ad and other placements when alternatives exist. Only mouse hover pauses rotation; touch interaction keeps it running. Filtering to one position removes these ads. Desktop keeps a horizontal banner at the bottom. The `Mainos` label has its own row above the artwork. Only the active ad is keyboard focusable. Images enter rotation after loading with dimensions larger than 1×1; failed images and tracking pixels are skipped. A mobile slot with no usable images collapses.
- Campaigns may define an `expiresAt` timestamp with an explicit timezone. Ads populate after mounting so static HTML cannot retain expired images during hydration. The ad store filters expired campaigns; `AdContainer` and [MobileAd](../src/lib/components/ui/MobileAd.svelte) refresh at the next expiry and when the tab regains focus or changes visibility. Björn Borg Black Week ends at midnight after `30.11.2026` in Finland; evergreen banners continue rotating.
- Position headings use distinct gradient stripes for forwards, defenders and goalies; retain their text labels so color is not the only distinction.
- The underlined player name and window icon open the player-details dialog; keep this action on the name rather than a separate card-footer button.
- Player details use compact stat grids and recent-game rows on the same ice-blue surfaces as the cards. Portalled overlays opt into `.dashboard-theme` to retain dashboard tokens outside the page wrapper. The dialog has an explicit close button, Escape dismissal, focus containment/return and background scroll locking.
- The player list offers `Kortit` and `Tiivis` views beside the position and sorting controls. `Kortit` keeps the default card grid and expansion controls. `Tiivis` shows every participating player in a short row with name, team, goals/assists/plus-minus (and recorded penalty minutes), or goalie save percentage and saves/shots, plus the matchup and result. Player names still open details and the stats button switches views inside the row. Both modes share the same player data and keep mobile ads between position groups. The browser remembers the choice in `player-view-mode`; blocked browser storage leaves both modes usable. Compact loading placeholders follow the row layout.
- The player list uses a responsive CSS grid. Swiper remains a dependency but is not the current player-list layout.
- Use the game's recorded state to distinguish upcoming, live and completed results. Include scoreless participants and exclude scratches/unused backups.
- Empty states show future Finnish-team games and eligible recent news. News disappears when no verified story qualifies. See [Player data](PLAYER_DATA.md) and [News](DAILY_NEWS.md).

## Accessibility and interaction

Use semantic headings, real buttons/links and visible focus. Supply labels for icon-only controls. Ensure nested card actions do not accidentally flip the card, and keep keyboard flipping and modal close/focus behavior usable. Verify long Finnish names and narrow screens without horizontal page overflow.

Loading, initial failure and background-refresh failure need distinct treatment. Results show card-shaped skeletons from the initial server render through date loading, with two visible on mobile and four on larger screens. Placeholders mirror the compact card layout and use a subtle shimmer that stops for reduced motion. One status message announces loading; decorative skeletons stay hidden from assistive technology. Use `Notice variant="recovery"` with an optional `actions` snippet for nonblocking refresh failures or stale cached data. It owns the compact dashboard surface, information icon, muted text and inline retry styling on both results and standings. Keep the visible results and never erase good data while a background request runs. Do not use color as the only indication of win/loss or freshness. Respect reduced-motion preferences when changing animation.

Test responsive behavior and interactions using [Testing](TESTING.md). This guide describes conventions and checks; it does not claim a completed accessibility certification or measured performance score.
